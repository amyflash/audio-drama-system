实现方案：三层CORS策略
================================================================================

优先级 1: 环境变量明确指定 (最优先)
─────────────────────────────────
  ALLOW_ORIGINS=https://app.com,https://api.app.com
  → 支持多个前端应用

优先级 2: ENV环境自动配置 (推荐)
────────────────────────────
  ENV=development  → 自动允许 http://localhost:5173
  ENV=production   → 自动禁用CORS (同域)

优先级 3: 留空使用推荐 (最灵活)
──────────────────────────
  ALLOW_ORIGINS=   → 使用上述自动策略

实现代码 (backend/app/main.py):
────────────────────────────
  def get_cors_config():
      env = os.getenv("ENV", "development")
      origins_str = os.getenv("ALLOW_ORIGINS", "")
      
      # 策略1: 明确指定
      if origins_str:
          return origins_str.split(",")
      
      # 策略2: 开发自动配置
      if env == "development":
          return ["http://localhost:5173", "http://127.0.0.1:5173"]
      
      # 策略3: 生产禁用CORS
      return []

  - withCredentials: true
  - Authorization header 设置

  - Nuxt 设置 ssr: false
  - 后端 SPAMiddleware 启用

   ✅ 优雅: 生产环境完全无需CORS

5. 易于维护
   ❌ 传统: API版本变更需要协调前后端
   ✅ 优雅: 前后端版本统一，一起部署

技术亮点
================================================================================

✨ 代理模式
  - Nuxt devProxy 拦截 /api/** 请求
  - 转发到后端，浏览器察觉不到
  - 开发环境零跨域

✨ 同域部署
  - 后端同时 serve 前端 SPA 和 API
  - 完全同域，浏览器无跨域认知
  - 生产环境最优

✨ SPA 路由 Fallback
  - SPAMiddleware 捕获所有非API请求
  - 返回 index.html (SPA客户端路由)
  - 支持刷新页面不404

✨ 环境自动适应
  - 根据 ENV 变量自动选择CORS策略
  - 开发时自动允许localhost
  - 生产时自动禁用CORS
